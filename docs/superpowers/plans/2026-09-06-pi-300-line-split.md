> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring every source and test file in the Pi integration (`pi/**` and `scripts/tests/pi-*`, `scripts/tests/test_figma_*`) to ≤ 300 lines with zero behavior change, and add a gate that keeps it that way.

**Architecture:** Pure move-refactor using one pattern everywhere: *context-passing modules + thin facade*. Each oversized class's method bodies move verbatim into topic modules as functions whose first parameter is a small context object; the original class file becomes a facade that keeps every public method (one-line delegation) and re-exports every symbol that tests or sibling modules import today. Call sites and tests therefore do not change (except where a test file itself is split).

**Tech Stack:** Node 24 / TypeScript 5.9 (`strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, ESM with `.js` specifiers) for `pi/github-issue-worker`; Pi extension TypeScript (loaded by Pi's own loader, `.ts` specifiers, no tsc) for `pi/agent/extensions`; Python 3.10+ stdlib for the figma skill; bash for `scripts/tests`.

**Spec:** Inline — §Spec below. Derived from the user's constraints (2026-09-06: "cap on line of code to 300", "always work on the worktree", "use other model while fanning out subagents") and the architecture review of `pi/` performed in the same session.

exit "$FAIL"
